最稳方案（推荐）
1. 建一个独立仓库作为共享配置源，例如 example-github-standards。
2. 把 .github 下需要共享的内容迁到这个仓库。
3. 在测试服和正式服都用 git subtree 拉取到各自 .github 目录。
4. 每次改规则只改共享仓库，再在两个项目执行 subtree pull 同步。

为什么推荐 subtree
1. 不会出现 submodule 常见的“忘记更新子模块指针”问题。
2. 仓库直接看到完整文件，日常开发体验更顺。
3. 可以按项目做少量本地差异，不会完全锁死。

可选方案
1. 轻量脚本同步（适合先跑起来）  
用 rsync 做单向覆盖，把正式服或测试服设成源；配合 git diff 检查。
2. submodule（强一致但维护成本高）  
适合你们团队已经习惯 submodule。
3. CI 自动镜像同步  
在“源仓库”变更 .github 后自动推送到另一个仓库，适合长期治理。
